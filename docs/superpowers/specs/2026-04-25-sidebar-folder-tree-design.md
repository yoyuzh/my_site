# 侧边栏文件夹树设计

## 目标

在工作台左侧侧边栏的“文件 Files”导航项下新增一个仅展示文件夹的树形目录导航。
第一版目标是让用户可以在侧边栏中展开目录、定位当前目录，并通过点击目录切换右侧文件页内容，而不引入新的后端接口或第三方树组件。

## 范围

- 仅在 `frontend/` 实现。
- 树中只显示文件夹，不显示文件。
- 支持展开/收起目录节点。
- 支持把展开状态持久化到 `localStorage`。
- 当当前目录为深层路径时，自动展开其祖先目录。
- 点击树节点后，切换文件页当前目录。
- 复用现有 `/api/files/list` 接口做目录懒加载。

不在本轮范围内：

- 拖拽移动目录
- 多选、框选、键盘导航
- 虚拟滚动
- 独立后端树接口
- 在非文件页中复用目录树选择器

## 当前约束

- 侧边栏目前由 `frontend/src/components/workspace/WorkspaceSidebar.tsx` 渲染，`文件 Files` 是普通导航项。
- 文件页状态当前由 `frontend/src/pages/Files.tsx` 持有，核心目录状态是 `currentPath`。
- 前端现有 `frontend/src/lib/files.ts` 已提供 `listFiles(path, page, size)`，返回指定目录下的文件和文件夹。
- 后端现有 `/api/files/list` 已按路径分页返回目录内容，前端可以直接过滤 `directory === true` 得到目录节点。

## 设计原则

- 不改动后端接口契约。
- 不引入 `react-arborist` 等第三方树组件。
- 目录树只负责目录导航，不接管文件页的业务操作。
- 持久化只保存展开路径，不缓存整棵树数据。
- 懒加载优先，避免在侧边栏一次性读取整棵目录树。

## 组件拆分

- `frontend/src/components/workspace/WorkspaceSidebar.tsx`
  继续作为工作台侧边栏入口，负责导航布局，并在“文件 Files”项下挂载目录树。

- `frontend/src/components/workspace/WorkspaceFolderTree.tsx`
  新增目录树容器，负责：
  - 当前路径感知
  - 展开路径集合管理
  - 节点数据缓存
  - 祖先自动展开
  - 与 URL 的目录参数同步

- `frontend/src/components/workspace/WorkspaceFolderTreeNode.tsx`
  新增单节点组件，负责：
  - 节点视觉呈现
  - 展开按钮
  - 加载中状态
  - 选中态
  - 点击行为

## 路由与路径同步

文件页增加目录 query 参数作为当前目录的稳定来源：

- 路由仍保持 `/dashboard/files`
- 当前目录通过 `?path=/文档/项目` 传递

规则如下：

- 文件页加载时，优先读取 URL 中的 `path`，没有时回落到 `/`
- 点击目录树节点时，更新 URL query
- 文件页中的面包屑、双击目录进入、创建文件夹等行为更新当前目录后，也同步写回 URL
- 侧边栏目录树通过路由感知当前目录，因此刷新页面后仍能恢复选中目录

## 节点数据模型

目录树节点使用逻辑路径作为稳定主键，而不是文件 id。

建议的前端节点结构：

```ts
type FolderNode = {
  path: string;
  name: string;
  children: FolderNode[] | null;
  childrenStatus: 'unknown' | 'has-folders' | 'empty' | 'loading' | 'error';
};
```

说明：

- `path`：目录逻辑路径，如 `/文档/项目`
- `name`：目录名称，根目录固定为 `/`
- `children`：已加载的子目录列表，未加载时为 `null`
- `childrenStatus`：
  - `unknown`：尚未检查是否有子文件夹
  - `has-folders`：存在子文件夹，可展开
  - `empty`：没有子文件夹，不显示展开按钮
  - `loading`：正在读取子目录
  - `error`：读取失败，可重试

## 懒加载策略

目录树不一次性请求所有目录，只在需要时按路径加载。

加载规则：

1. 根目录 `/` 在目录树初始化时加载一次。
2. 节点首次尝试展开时，请求该节点路径下的目录列表。
3. 返回结果只保留 `directory === true` 的项。
4. 如果过滤后为空，则节点标记为 `empty`，并且之后不再显示展开按钮。
5. 如果有子目录，则节点标记为 `has-folders`，并缓存子节点。

为了满足“空目录不能展开，并且不显示展开按钮”，目录树在拿到某一层的直接子目录后，需要补一轮轻量探测来判断每个子目录是否仍包含子文件夹。

探测规则：

- 对当前层每个子目录额外请求一次 `listFiles(childPath, 0, 1)`
- 只要返回结果里存在 `directory === true` 的项，就把该子目录标记为 `has-folders`
- 否则标记为 `empty`
- 节点在 `unknown` 或探测中的阶段不显示可点击展开按钮，只显示目录本身

分页策略：

- 第一版直接使用较大的 `size`，例如 200，仅作为目录树懒加载页大小。
- 目录树不做多页加载。
- 如果单目录子文件夹量未来明显超过当前页大小，再单独扩展。

## 展开状态持久化

展开状态以路径数组形式保存到 `localStorage`。

建议 key：

- `workspace-folder-tree-expanded-paths`

规则：

- 仅保存已展开路径集合，例如 `["/", "/文档", "/文档/项目"]`
- 根目录 `/` 始终视为存在且默认展开
- 应用启动时读取并恢复
- 如果某个路径已不存在，则在后续加载失败或无法命中节点时自动忽略，不阻塞目录树渲染
- 关闭节点时同步更新持久化内容

## 当前路径祖先自动展开

当当前目录是深层路径时，需要确保用户能在侧边栏中看到它所在的位置。

例如当前目录为：

- `/文档/项目/A`

则自动把以下路径加入展开集合：

- `/`
- `/文档`
- `/文档/项目`

处理流程：

1. 从当前路径拆出所有祖先路径
2. 把这些祖先路径并入展开集合
3. 按祖先顺序逐级确保节点已加载
4. 当目标节点出现后，将其标记为选中

如果某一级目录不存在：

- 停止继续向下加载
- 不让整个目录树报错
- 文件页自身仍按现有逻辑处理当前路径是否有效

## 交互规则

- 点击文件导航项本身：进入 `/dashboard/files`，如果 URL 没有 `path`，则使用 `/`
- 点击目录节点名称：切换当前目录
- 点击展开按钮：只控制展开/收起，不切换当前目录
- 当前目录节点高亮
- 祖先目录不因为高亮而自动折叠
- 空目录显示为普通目录节点，不显示展开按钮
- 目录树中永远不显示普通文件

## 与文件页的联动

本轮继续让 `frontend/src/pages/Files.tsx` 作为文件页状态 owner。

需要做的联动：

- `Files.tsx` 从 URL query 读取并维护 `currentPath`
- 当文件页内部切换目录时，同步更新 query
- 目录树通过 `useLocation` / `useSearchParams` 感知当前路径

目录树刷新策略：

- 当前目录创建文件夹后，刷新当前目录对应树节点
- 目录重命名后，刷新其父目录节点；如果当前目录就是该目录，同时更新当前路径
- 目录移动后，刷新源父目录和目标父目录
- 删除目录后，刷新其父目录
- 从回收站恢复目录后，刷新恢复目标的父目录

本轮不要求目录树实时响应所有后台事件；只要求在文件页内由当前用户触发的目录变更后保持基本同步。

## 错误处理

- 单节点加载失败时，仅在该节点位置显示轻量错误状态或重试按钮
- 根目录加载失败时，侧边栏显示整体错误提示和重试入口
- `localStorage` 数据损坏时，回退为空展开集合
- URL 中的 `path` 非法时，前端回退到 `/`

## 验证

- 进入 `/dashboard/files`，根目录正确显示
- 展开多个目录并刷新页面，展开状态仍保留
- 直接访问深路径 URL，祖先目录自动展开，当前目录正确高亮
- 空目录显示但不出现展开按钮
- 非空目录仅在存在子文件夹时显示展开按钮
- 树中不显示任何普通文件
- 在文件页创建文件夹后，左侧树能刷新出新目录
- 在文件页重命名或移动目录后，左侧树结构同步更新
- 运行：
  - `cd frontend && npm run lint`
  - `cd frontend && npm run build`

## 实现顺序

1. 新增目录树组件和节点组件
2. 给文件页接入 `path` query 同步
3. 在侧边栏文件导航项下接入目录树
4. 完成懒加载、持久化、祖先自动展开
5. 把文件页中的目录变更动作和树刷新联动起来
6. 运行前端校验并手动验证
