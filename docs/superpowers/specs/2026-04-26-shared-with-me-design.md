# Cloudreve 风格分享与“与我共享”升级设计

## 目标

- 在现有分享能力基础上，升级为更接近 Cloudreve 的分享模型。
- 分享者可以创建站内分享链接，并配置密码、过期时间、下载或导入成功后自动失效。
- 分享者可以在 `我的分享` 中查看和管理自己发出的分享。
- 接收方可以在分享页手动把分享保存到 `与我共享`。
- `与我共享` 保存的是分享快捷入口，不复制文件内容，不绕过原分享规则。

## 非目标

- 不把分享系统升级成用户级协作权限系统。
- 不把 `与我共享` 做成 workspace 文件树或真实目录节点。
- 不把保存到 `与我共享` 等同于“导入到网盘”。
- 不做“打开过一次就自动进入与我共享”的访问历史列表。
- 不在本轮实现去重后的“真实查看人数”；展示口径先使用访问次数。

## 已确认的产品口径

### 分享创建

分享链接由分享者主动创建，站内生成可访问的分享 URL。

分享可配置的规则为：

- 使用密码保护链接
- 超时自动过期
- 下载或导入成功后自动失效

### 我的分享

`我的分享` 展示用户自己创建的分享，并提供管理入口。

分享者可查看：

- 分享文件
- 分享有效期
- 分享 URL
- 分享密码
- 分享访问次数
- 当前状态

分享者可执行：

- 打开
- 复制链接
- 编辑策略
- 取消分享

### 与我共享

`与我共享` 采用 Cloudreve 风格的“保存快捷入口”模式。

规则如下：

- 接收方必须在分享页中手动点击“保存到与我共享”
- 不自动根据访问历史生成条目
- 保存的是分享快捷入口，不是文件副本
- 不保存密码
- 不绕过原分享的密码、有效期、下载/导入权限规则
- 如果原分享失效、过期或被取消，`与我共享` 条目保留，但显示为失效

### 自动失效

`下载或导入成功后自动失效` 的消费时机固定为：

- 下载成功后
- 导入成功后

以下行为不会触发自动失效：

- 打开分享页
- 浏览分享信息
- 验证密码但未下载/未导入
- 保存到 `与我共享`

### 访问统计

本轮前台展示的“被查看人数”先按 `访问次数` 实现。

原因：

- 当前后端已有 `viewCount`
- 真正去重的查看人数需要额外身份/设备去重策略
- 对这轮分享升级不是必要前提

## 方案对比

### 方案 1：访问历史型

- 打开过分享就自动进入 `与我共享`
- 实现最省
- 但会污染 `与我共享`，也不符合 Cloudreve 的使用模型

### 方案 2：快捷入口型（选定）

- 接收方手动保存分享到 `与我共享`
- 保存的是分享引用，而不是文件副本
- 打开时继续执行原分享规则
- 与 Cloudreve 的 `Shared with me` 最接近

### 方案 3：协作授权型

- 直接把分享升级成面向用户/用户组的授权关系
- 可以形成真正的“共享给我文件系统”
- 但复杂度明显超出本轮，且会改变后端的业务边界

本轮选择 `方案 2`。

### 当前缺口

### 模块边界要求

根据当前架构文档，本轮能力应继续留在 `files.sharing`：

- 分享本体规则属于 `files.sharing`
- `与我共享` 本质是“用户保存的分享入口”，不是 workspace 树节点
- 不应把这条能力回流到 `files.workspace`

## 后端设计

## 1. 分享本体增强

继续复用 `files.sharing` 中现有分享主模型，并新增一个策略字段：

- `expireAfterConsume: boolean`

语义固定为：

- 当分享下载成功或导入成功后，分享立即失效

建议实现方式：

- 为分享增加消费后失效标记，例如 `consumedAt`
- 判断分享是否可用时，同时检查：
  - 是否已过期
  - 是否已取消
  - 是否已消费失效

这样比直接物理删除更稳定，因为：

- `我的分享` 仍可查看历史状态
- `与我共享` 也能展示“已失效”

## 2. 与我共享快捷入口模型

新增一个保存分享入口的独立模型，建议语义名为：

- `SavedShareShortcut`

建议字段：

- `id`
- `recipientUserId`
- `shareId`
- `shareToken`
- `savedAt`

必要约束：

- `recipientUserId + shareId` 唯一

业务规则：

- 同一用户重复保存同一分享，按幂等处理
- 删除 `与我共享` 条目只删除快捷入口，不影响分享本体

## 3. API 设计

在 `files.sharing` 的 v2 路由下新增以下接口。

### 保存到与我共享

- `POST /api/v2/shares/{token}/save`

行为：

- 当前登录用户保存该分享到 `与我共享`
- 若分享需要密码，则必须在请求中携带密码并校验通过
- 若已保存，则返回现有条目

### 列出与我共享

- `GET /api/v2/shares/shared-with-me`

返回用户已保存的分享入口列表。

每项建议包含：

- `id`
- `token`
- `shareName`
- `ownerUsername`
- `passwordRequired`
- `allowImport`
- `allowDownload`
- `expiresAt`
- `createdAt`
- `savedAt`
- `viewCount`
- `status`
- `file`

其中 `status` 至少包含：

- `ACTIVE`
- `EXPIRED`
- `CONSUMED`
- `REMOVED`

如果分享本体被取消删除，可映射为 `REMOVED`。

### 与我共享详情

- `GET /api/v2/shares/shared-with-me/{id}`

用于前端在打开前获取当前状态，或详情页展示。

### 从与我共享移除

- `DELETE /api/v2/shares/shared-with-me/{id}`

只删除当前用户的快捷入口。

## 4. 分享管理接口增强

保留现有 `/api/v2/shares` 主路径，并增强以下能力：

- `POST /api/v2/shares`
  - 增加 `expireAfterConsume`
  - 支持密码和过期时间一起提交
- `PATCH /api/v2/shares/{id}/policy`
  - 从只改 `maxDownloads`
  - 扩展为可修改：
    - 密码
    - 过期时间
    - `expireAfterConsume`
    - 下载上限

说明：

- 为了不引入多条零碎接口，这里更适合把策略更新做成一个完整 policy 更新请求
- 不修改 token，不做“重新生成链接”

## 5. 分享访问逻辑调整

### 公开查看

- 打开分享页时，继续沿用当前 `getShare`
- 如果需要密码，默认不返回文件细节或敏感动作权限

### 保存到与我共享

- 若分享有密码：
  - 仅在密码校验通过后允许保存
- 保存时不缓存密码
- 后续从 `与我共享` 打开时，若仍需要密码，仍然要求重新输入

### 下载 / 导入后的自动失效

- 下载成功后：
  - 记录下载次数
  - 若 `expireAfterConsume=true`，标记分享失效
- 导入成功后：
  - 记录下载/消费次数
  - 若 `expireAfterConsume=true`，标记分享失效

失败情况不消费：

- 下载请求发起但实际失败
- 导入校验失败
- 密码错误

## 前端设计

弹窗升级为规则型表单，包含三项开关：

- 超时自动过期

- 分享 URL

## 4. 与我共享页面

新增真实页面替换当前占位页。

- 跳转回分享详情页

- 有效

## 风险点

- 自动失效的消费时机必须准确，不能在查看页或验证密码时提前触发
- 保存到 `与我共享` 不能缓存密码，否则会变成绕过分享保护
- `与我共享` 必须和“导入到网盘”保持两套明确语义
- 如果分享本体被删除，快捷入口应显示已取消，而不是前端直接报错空白
- 策略更新接口如果只做局部 patch，容易继续碎片化；建议一次性收成统一 policy DTO
